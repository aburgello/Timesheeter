How it works

Where job numbers, films and countries come from

How the timesheet finds the right job, film and country for every piece of work — in Management and in Legacy.

Every piece of work — a trailer, a poster, a campaign — starts life in Wrike, the project management tool where all of our folders and tasks live. Each folder and task carries a job number — an XY code such as XY025563. When someone records time, the timesheet has to know three things about that task: which job it is, which film it's for, and which country the work is in. This is how it works those out.

Job number

The job's identity

XY025563

The XY code is the job's real identity. It never changes; the description around it can, and does.

Film

The project it belongs to

“The Odyssey”

Country

The territory

“UK”, “Ireland”, “UK, Ireland”

The country the work is for, read deliberately from the task — never guessed from the notes.

2Wrike's folder tree — where it all starts

Wrike organises our work as a tree of folders: a studio at the top, then the film, then a folder per job, and inside that the individual tasks people work on. Where a folder sits in the tree tells us nearly everything — which studio, which film, and which arm of the studio it belongs to.

UNIVERSAL UKstudio
└─2026year — not a film
└─The Odysseyfilm
└─XY025563_Germany_Launch_Assetsjob
└─… individual tasks …

The “2026” year folders are organisational, not films — the app skips them when deciding what a job belongs to. A job's film is the folder just below the studio on the way down to the job.

3Management — how the Job Book fills up

Management is the “control room” side of the app. Its most important list is the Job Book: the shared record of every job we've seen, with its number, film and client. The book is kept in step with Wrike by a scan you can run any time — “Scan Wrike for job numbers”. Here's what the scan does:

  1. It walks every folder in Wrike, top to bottom.
  2. It finds every folder whose name contains an XY code.
  3. It reads the job description off the folder name, after the code (_Germany_Launch_Assets becomes “Germany Launch Assets”).
  4. It looks at where the folder sits in the tree to learn the studio, the film and which arm of the studio it belongs to — the studio folder's name decides the client (see the note below).
  5. It puts it all together as one clean line, the way the timesheet likes it: The Odyssey : XY025563, Germany Launch Assets.
  6. It compares its findings with the Job Book — jobs we haven't seen yet are offered as new, and jobs already in the book whose details disagree with Wrike are flagged for review.
Territory means the country. The studio folder's name carries a region marker — “UNIVERSAL UK”, “UNIVERSAL”, “UNIVERSAL AUSTRALIA” — and that decides the client (“Universal Pictures UK”, “Universal Pictures International”) and how the job is described (UK - Sky VIP). That marker is the studio arm, not the territory. The territory — the country the work is for, such as UK or Ireland — is read separately, from the task itself, and is never guessed from a sentence.

4Legacy — the timesheet we use

Legacy is the timesheet we actually use. It works a bit differently from the scan in Management, because the tasks there don't always carry everything with them. When time is pulled in from Wrike, each row gets its details like this:

  1. It reads the XY code off the task — from the task's dedicated Job Number field if it has one, otherwise from the task name.
  2. It looks the code up in the Job Book. If the job is already there, the book's version wins — one job number, one film, one client, shared by everyone. A bare XY025563 from an old record still picks up the full name and film the book holds for that code.
  3. If the code isn't in the book yet, it's added automatically the first time it's seen — the book learns from real use, and never overwrites a row that's already there.
  4. It reads the country deliberately — from the end of the task name or a dedicated Country field. It is never guessed from a sentence of notes; a task that deliberately carries no country simply gets an empty one to fill in.
  5. It fills in the film — from the job's registered name first, otherwise from the folder the task lives in.

The Job Book — one shared memory

  • It's the curated, editable list of every job we've encountered.
  • The first time a code appears anywhere, it's recorded automatically.
  • Once a job is in the book, the book wins over any fresh guess — because a human has already checked it.
  • Everything is matched on the XY code, so an old bare-code record inherits the film and client the book holds for the full entry — and a job can never be registered twice under two different names.
  • Corrections are made once, in Management, and apply everywhere — the timesheet, the tracker, the reports.

5When the book and Wrike disagree

Sometimes the Job Book and Wrike don't match — a folder was moved, renamed, or the book holds an older guess. The scan shows you both sides (the book's line and Wrike's), along with where in Wrike the folder actually lives, so you can judge which one is right. Then you choose, job by job:

Fix

Rewrite the book row to match Wrike. Use this when Wrike is right and the book is behind.

Keep

Keep the book as it is. Use this when the book is right and Wrike hasn't caught up. The decision is remembered, so the scan stops asking about that job on future runs.

6A job from start to finish

One code, XY025563, walked through both sides of the system:

XY025563 · “Germany Launch Assets”
In Wrike→The job folder XY025563_Germany_Launch_Assets sits under The Odyssey, under Universal.
Management scan→Reads code XY025563, description “Germany Launch Assets”, film “The Odyssey”, studio arm International → the canonical line The Odyssey : XY025563, Germany Launch Assets.
Job Book→Code accepted as new → stored once, shared by everyone.
Legacy timesheet→A pulled task carries the bare XY025563 → the book supplies the film and the clean job name; the country is read from the task's own field.
Recording time→Anywhere in the app, typing XY025563 resolves to the same film, client and country — no one has to type them out.
